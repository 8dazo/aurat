# Aurat V1 runtime

## Promise

Point an OpenAI-compatible application at Aurat, record a real provider interaction once, replay it deterministically without contacting the provider, turn known-good behavior into a contract, exercise provider failures on demand, and validate a small subset against the live model for drift.

## Two test loops

### Deterministic loop

Run on every commit:

1. record representative interactions once;
2. replay them without the provider;
3. verify structural behavioral contracts;
4. inject failures/latency for error-path coverage.

### Live canary loop

Run nightly, pre-release, or on model/prompt changes:

1. select a deterministic capped subset of contract scenarios;
2. reconstruct each request from its baseline recording;
3. intentionally call the configured live provider;
4. analyze the fresh response using the same behavior model;
5. fail if contracted structure drifted.

`aurat canary --limit 5` makes at most five live provider calls. The default limit is 10. Selection sorts scenarios by fingerprint and takes the first N so a given contract produces a stable canary set.

Canary responses are kept in memory and do not overwrite baseline recordings. Network/provider connection failures are reported as `live_call` verification failures.

## Modes

- `live`: transparent proxy; no recording is persisted.
- `record`: proxy live traffic and append a recording to `.aurat/recordings.jsonl`.
- `replay`: never call the upstream provider; return the newest recording matching the request fingerprint.

## Matching

A V1 fingerprint contains the HTTP method, request path/query, and canonical request body. JSON object keys are sorted. `stream_options` remains a built-in ignored field because SDKs can add it without changing the semantic request. Authorization headers are not part of the fingerprint.

Optional `.aurat/config.json` rules can remove explicit volatile values before fingerprinting. Rules are explicit rather than semantic: V1 never guesses that two model requests are equivalent.

## Behavioral contracts

`aurat contract` builds a structural contract from the newest recording for every fingerprint. `aurat verify` compares the newest recording for each contracted fingerprint with that baseline and exits non-zero on meaningful structural changes.

The V1 contract covers HTTP status, normalized content type, streaming mode, response kind, tool-call names, finish reasons, and top-level keys for structured JSON assistant content.

## Fault injection

Use `--fault` or `AURAT_FAULT` to bypass both replay storage and the upstream provider with a deterministic failure:

- `rate-limit`: HTTP 429 with an OpenAI-style error and `Retry-After: 1`;
- `server-error`: HTTP 500;
- `malformed-json`: HTTP 200 with an intentionally truncated JSON body;
- `empty-response`: HTTP 200 with an empty body;
- `connection-reset`: closes the client connection without a provider call.

Use `--delay-ms` or `AURAT_DELAY_MS` to add deterministic latency before normal handling or fault injection.

## Recording format

Recordings use format version 2 and store response bytes as base64. This keeps JSON, SSE, and other response bodies byte-safe. Replay remains backward-compatible with version 1 recordings where `response.body` was plain UTF-8 text.

## Streaming

Record mode forwards chunks as they arrive and persists the complete byte stream before ending the client response. Replay preserves the recorded event-stream bytes. V1 does not yet reproduce the provider's original inter-chunk timing.

## Authentication

By default the proxy forwards the incoming `Authorization` header. `AURAT_UPSTREAM_API_KEY` (or `OPENAI_API_KEY`) overrides it. The canary runner uses that provider key directly when making live calls.

## Debugging

Proxy responses expose `x-aurat-mode`, `x-aurat-replay`, `x-aurat-fingerprint`, and, for injected HTTP failures, `x-aurat-fault`.

## Not in V1 yet

- semantic/generalized replay;
- tool/service virtualization;
- trace import from OpenTelemetry/Langfuse/LangSmith;
- original streaming timing simulation;
- GitHub-native PR annotations/release gates.
