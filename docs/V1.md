# Aurat V1 runtime

## Promise

Point an OpenAI-compatible application at Aurat, record a real provider interaction once, and replay it deterministically in development or CI without contacting the provider again. Turn known-good provider behavior into a contract that can catch meaningful changes later.

## Modes

- `live`: transparent proxy; no recording is persisted.
- `record`: proxy live traffic and append a recording to `.aurat/recordings.jsonl`.
- `replay`: never call the upstream provider; return the newest recording matching the request fingerprint.

## Matching

A V1 fingerprint contains the HTTP method, request path/query, and canonical request body. JSON object keys are sorted. `stream_options` remains a built-in ignored field because SDKs can add it without changing the semantic request. Authorization headers are not part of the fingerprint.

Optional `.aurat/config.json` rules can remove explicit volatile values before fingerprinting:

```json
{
  "match": {
    "ignoreBodyPaths": ["metadata.request_id", "messages.*.id"],
    "ignoreQueryParams": ["trace_id"]
  }
}
```

Rules are explicit rather than semantic: V1 never guesses that two model requests are equivalent.

## Behavioral contracts

`aurat contract` builds a contract from the newest recording for every fingerprint. For OpenAI-style chat responses, the contract currently captures:

- HTTP status;
- normalized content type;
- streaming vs non-streaming;
- response kind: empty, text, JSON, or tool calls;
- tool-call names;
- finish reasons;
- top-level keys for structured JSON assistant content.

`aurat verify` compares the newest recording for each contracted fingerprint with that baseline. Missing scenarios and behavior changes fail verification. New/uncontracted fingerprints are reported but do not fail V1 by default.

This is deliberately structural rather than semantic. Aurat should catch software-level and orchestration-level regressions deterministically before introducing judge-model-based evaluation.

## Recording format

Recordings use format version 2 and store response bytes as base64. This keeps JSON, SSE, and other response bodies byte-safe. Replay remains backward-compatible with version 1 recordings where `response.body` was plain UTF-8 text.

## Streaming

Record mode tees the provider stream: one branch is sent to the application while the other is persisted. Replay preserves the recorded event-stream bytes. V1 does not yet reproduce the provider's original inter-chunk timing.

## Authentication

By default Aurat forwards the incoming `Authorization` header. Set `AURAT_UPSTREAM_API_KEY` (or `OPENAI_API_KEY`) to override it when forwarding upstream.

## Debugging

Responses expose:

- `x-aurat-mode`: current runtime mode;
- `x-aurat-replay`: `hit`, `miss`, or `bypass`;
- `x-aurat-fingerprint`: deterministic request fingerprint.

`aurat inspect` summarizes captured endpoints, models, and OpenAI-style tool calls.

## Not in V1 yet

- semantic/generalized replay;
- tool/service virtualization;
- fault injection;
- provider/model drift canary runner;
- OpenTelemetry/Langfuse/LangSmith trace import;
- original streaming timing simulation.
