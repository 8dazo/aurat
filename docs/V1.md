# V1 runtime

Aurat V1 begins with one narrow promise:

> Point an OpenAI-compatible client at Aurat, record a real interaction once, and replay the same interaction deterministically in local development or CI without calling the provider again.

## Modes

### `live`

A transparent proxy. Requests go to the provider and are not persisted.

### `record`

Requests go to the provider. Aurat stores a cassette containing the normalized request fingerprint and the raw provider response.

### `replay`

Aurat never contacts the provider. It returns the previously recorded response for the exact request fingerprint, or an explicit replay-miss error.

## Fingerprint

V1 fingerprints:

- HTTP method
- request path, including query string
- request body

JSON object keys are canonicalized before hashing. Authorization headers are intentionally excluded so the same scenario can replay across developer and CI credentials.

## What V1 already preserves

- provider status code
- response headers safe to proxy
- raw response bytes
- SSE/event-stream payloads
- OpenAI-compatible paths, not only chat completions

V1 does not yet reproduce original streaming chunk timing. Event-stream content is recorded exactly, but replay may arrive faster than the live provider.
