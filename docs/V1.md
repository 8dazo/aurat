# Aurat V1 runtime

## Promise

Point an OpenAI-compatible application at Aurat, record a real provider interaction once—or import captured GenAI telemetry—replay it deterministically without contacting the provider, turn known-good behavior into a contract, exercise provider failures on demand, validate a small subset against the live model for drift, and gate pull requests on the result.

## Two test loops

### Deterministic loop

Run on every commit:

1. collect representative interactions via Aurat record mode or OpenTelemetry import;
2. replay them without the provider;
3. verify structural behavioral contracts;
4. inject failures/latency for error-path coverage;
5. gate the pull request if contracted behavior regresses.

### Live canary loop

Run nightly, pre-release, or on model/prompt changes:

1. select a deterministic capped subset of contract scenarios;
2. reconstruct each request from its baseline recording;
3. intentionally call the configured live provider;
4. analyze the fresh response using the same behavior model;
5. fail if contracted structure drifted.

`aurat canary --limit 5` makes at most five live provider calls. The default limit is 10. Canary responses stay in memory and do not overwrite baseline recordings.

## Existing-stack bootstrap

`aurat import-otel traces.json` consumes OTLP JSON exports using current GenAI semantic attributes and converts replayable `chat` spans into Aurat's OpenAI-compatible recording format. This gives teams an adoption path from their existing observability stack rather than requiring immediate proxy migration.

Message content is opt-in in OpenTelemetry and may contain sensitive data. Aurat only imports spans with both input and output messages and reports explicit skip reasons for incomplete traces. See `docs/OPENTELEMETRY.md`.

## GitHub regression gate

The root `action.yml` makes the repository directly usable as a composite GitHub Action. It runs `aurat verify`, writes the exact regression diff to the Actions job summary, and exits with the verifier status. The action intentionally makes no live provider calls.

## Modes

- `live`: transparent proxy; no recording is persisted.
- `record`: proxy live traffic and append a recording to `.aurat/recordings.jsonl`.
- `replay`: never call the upstream provider; return the newest recording matching the request fingerprint.

## Matching

A V1 fingerprint contains the HTTP method, request path/query, and canonical request body. JSON object keys are sorted. `stream_options` remains a built-in ignored field because SDKs can add it without changing the semantic request. Authorization headers are not part of the fingerprint.

Optional `.aurat/config.json` rules can remove explicit volatile values before fingerprinting. Rules are explicit rather than semantic: V1 never guesses that two model requests are equivalent.

## Behavioral contracts

`aurat contract` builds a structural contract from the newest recording for every fingerprint. `aurat verify` compares the newest recording for each contracted fingerprint with that baseline and exits non-zero on meaningful structural changes.

The V1 contract covers HTTP status, normalized content type, streaming mode, response kind, tool-call names, finish reasons, and top-level keys for structured JSON assistant content.

## Fault injection

Use `--fault` or `AURAT_FAULT` for deterministic `rate-limit`, `server-error`, `malformed-json`, `empty-response`, or `connection-reset` failures. Use `--delay-ms` or `AURAT_DELAY_MS` for deterministic latency.

## Recording format

Recordings use format version 2 and store response bytes as base64. Replay remains backward-compatible with version 1 plain-UTF-8 recordings.

## Streaming

Record mode forwards chunks as they arrive and persists the complete byte stream before ending the client response. Replay preserves recorded event-stream bytes. Imported streaming OTel spans are normalized into deterministic SSE. V1 does not yet reproduce original inter-chunk timing.

## Authentication

By default the proxy forwards the incoming `Authorization` header. `AURAT_UPSTREAM_API_KEY` (or `OPENAI_API_KEY`) overrides it. The canary runner uses that provider key directly when making live calls.

## Not in V1 yet

- semantic/generalized replay;
- tool/service virtualization;
- Langfuse/LangSmith-specific adapters on top of trace normalization;
- original streaming timing simulation;
- a pinned public V1 release/tag.
